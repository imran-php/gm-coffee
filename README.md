# GM COFFEE — демонстрационный интернет-магазин

**Демо:** https://genuine-fenglisu-84d630.netlify.app

Готовый статический сайт для презентации клиенту. Каталог, корзина, оформление доставки, тестовый сценарий СБП. Кремово-кофейная палитра и оригинальный векторный логотип из предоставленных макетов.

**Это не работающий сервис доставки. СБП и iiko не подключены, деньги не списываются, заказ в кассу не отправляется.**

## Показать клиенту через Netlify Drop

1. Распакуйте архив. Найдите папку `gm-coffee`, внутри которой непосредственно лежит `index.html`.
2. Откройте https://app.netlify.com/drop и войдите в свой аккаунт Netlify.
3. Перетащите всю папку `gm-coffee` в область загрузки. Не только файл `index.html`: ему нужны папки `css`, `js` и `assets`.
4. Откройте полученный адрес проекта на `netlify.app`. Перед отправкой клиенту проверьте ссылку в приватном окне: у проекта могут быть настройки ограниченного доступа.

Здесь нет сборки, npm-зависимостей, ключей или настройки базы данных. Загружаются уже готовые HTML, CSS, JS и SVG. Чтобы обновить показ, исправьте файлы и загрузите обновлённую папку в раздел развёртываний того же проекта.

Официальная инструкция: https://docs.netlify.com/start/quickstarts/netlify-drop-quickstart/

Если отдельно получен `gm-coffee-preview.html`, это автономная копия: её можно открыть в браузере для локального показа. В ней встроены все изображения, стили и скрипты. Редактировать удобнее многокомпонентный проект из архива, а не этот автоматически собранный файл. Не смешивайте автономный HTML с `_headers` многокомпонентной версии: их политики CSP различаются.

## Что уже реализовано

- Полное меню: **64 напитка в 9 категориях**, поиск, сортировка, избранное и дозагрузка карточек без потери остальных позиций.
- Кликабельные карточки, выбор доступных вариантов объёма и количества, добавление прямо из каталога.
- Корзина с изменением количества, удалением, подтверждением полной очистки и корректным пересчётом. Разные объёмы хранятся отдельными строками.
- Форма доставки и демонстрационного самовывоза, проверка обязательных полей и телефона, комментарий, желаемое время получения.
- Итоговая стоимость доставки показывается **до** тестовой оплаты.
- Кнопка заполнения вымышленными данными для удобной презентации.
- Демонстрация успешной и неуспешной оплаты СБП, повторная попытка и отмена без очистки корзины.
- Экран результата с явными пометками «симуляция оплаты» и «iiko не подключена». Переключаемые тестовые статусы приготовления/доставки и повтор заказа.
- Адаптация под телефон, закреплённая мобильная корзина, клавиатурное управление, нативные диалоги и режим уменьшения анимации.

## Сценарий презентации на 2–3 минуты

Откройте меню, переключите категорию и найдите капучино поиском. Выберите 350 мл, добавьте напиток и откройте корзину. Проверьте изменение цены при изменении количества. Перейдите к оформлению, нажмите «Заполнить всё тестовыми данными», подтвердите понимание тестового режима и перейдите к тестовой оплате.

Сначала покажите неуспешную оплату: заказ не появляется, корзина остаётся. Затем повторите попытку и покажите успешную тестовую оплату. На экране результата видны номер демозаказа, итоговая сумма и то, что отправки в iiko не было. Кнопкой переключите демонстрационные статусы.

Для следующего показа откройте внизу сайта «О демоверсии» → «Сбросить данные демонстрации».

## Где менять данные

- **`js/config.js`** — стоимость и порог доставки, интервалы времени, разрешённые способы получения, лимиты количества, будущие контакты. Это публичный файл, секретов здесь быть не должно.
- **`js/menu.js`** — названия, цены, варианты, категории и доступность напитков. Флаг `available: false` убирает возможность добавить позицию. Текущая демоверсия не синхронизирована со стоп-листом iiko.
- **`css/styles.css`** — цвета в `:root`, адаптивная сетка и всё оформление.
- **`assets/`** — оригинальные векторные логотипы и иллюстрации. Новые фото можно подключить через `image` у соответствующего товара.
- **`js/core.js`** — расчёт корзины, нормализация, поиск, проверка номера и экранирование.
- **`js/app.js`** — интерфейс и локальные сценарии показа.
- **`docs/INTEGRATION.md`** — план перехода к реальной оплате и передаче заказов в iiko. Это план, не установленная интеграция.

Поля контактов оставлены пустыми. Не добавлены неподтверждённые телефон, аккаунт, адрес или часы из старой полиграфии.

## Важные замечания к меню

Все цены взяты из **правой ценовой колонки** переданного меню. У клубничного коктейля выбрано **360 ₽**; в той же исходной строке напечатано и **300 ₽**. В карточке напитка и разделе о демо это расхождение отмечено. До реальных продаж нужна одна утверждённая цена.

При двух ценах варианты сопоставлены с заголовком `250 мл / 350 мл` для показа. Это не окончательное подтверждение фактических объёмов. При одной цене отображается «Одна порция»: например, эспрессо не получает придуманный объём 350 мл. Названия «Бамби вишня» и «Нут-кофе» сохранены как в источнике. В названии рафов добавлен префикс «Раф» для ясности вне своей категории; исходное название тоже сохранено в данных.

Составы, аллергенные признаки, сиропы и платные добавки не выдуманы. Иллюстрации не являются фотографиями конкретных напитков. Геометрия оригинального логотипа взята из клиентского PDF; файлы шрифтов не поставляются, используются системные гарнитуры.

## Данные и безопасность демо

Политика CSP запрещает сетевые API-запросы (`connect-src 'none'`) и обычную отправку HTML-форм. Страница не подключает сторонние изображения, шрифты, аналитику или сервисы. В QR-коде — только текст, не платёжная ссылка.

`localStorage` содержит только корзину, избранное и последний **обезличенный** тестовый заказ. Имя, телефон, адрес и комментарий остаются в памяти страницы, не сохраняются в историю и не отправляются на сервер. Для показа используйте вымышленные данные. Сам хостинг может вести технические журналы посещений. При недоступном localStorage корзина работает до закрытия/обновления страницы.

Лимиты демо: до 20 порций одного варианта и до 100 напитков в корзине. При инициализации некорректные строки и неизвестные варианты из локального хранилища отбрасываются. Цены пересчитываются по меню, а не из сохранённого поля `price`. Это **не защита реального магазина**: при запуске сервер обязан заново проверять весь заказ.

Файл `robots.txt`, метатеги и `_headers` отключают индексацию показа. Это не авторизация: ссылку может открыть любой, кому она доступна по настройкам Netlify.

## Проверки и локальная разработка

Открывать можно через локальный сервер:

```bash
python -m http.server 8080
```

Затем откройте `http://localhost:8080`. Зависимостей для сайта нет.

Проверки чистых функций и исходного меню:

```bash
node tests/core.test.cjs
```

Создать автономную HTML-копию после изменений:

```bash
python tools/build_single.py ../gm-coffee-preview.html
```

Для шаблона автономной копии автоматически рассчитываются CSP-хеши скриптов и стилей. Ручная правка встроенного кода нарушит эти хеши; пересоберите копию после изменений в исходных файлах.

Подробности выполненных проверок и их границы — в `docs/QA.md`. Netlify-проект из этой среды не публиковался, реальные транзакции и приём заказа кассой не тестировались.
